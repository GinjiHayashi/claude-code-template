# 進捗の報告

## 準備
1. 未読なら（圧縮で内容が消えた場合も）`docs/guidelines/workflow.md`（WF-01、WF-03・10・20〜25）を読む。

## 集計
2. `bash .claude/scripts/progress.sh` を実行し、資料の status、REQ と DES の対応、DES の実装状況（WF-10）、TASK の一覧、未解決事項を得る。
3. 「実装順の記録がある TASK」に挙がった TASK の「完了したこと」を読み、実装順を得る（WF-03、WF-20）。変更要求の実装順は、要件定義の実装順の後に続ける。

## 判定
4. WF-23 で次の作業を1つ決める。
5. WF-24 に当たる資料を探す。「プロジェクト全体の点検の材料」で WF-25 に当たるか判定する。
6. 残作業を実装順に並べる。`final` の DES がない REQ は「設計」、実装状況が `done` でない DES は「実装」とする。

## 報告
7. 次の形で報告する。根拠のない内容は書かない（WF-22）。ファイルは変更しない。
   - **現在地**: WF-01 のどの段階か（開発開始 / 要件定義 / 要件ごとの設計・実装 / 変更要求）を1行で。REQ と DES の完了数（例: REQ 2/5 完了、DES 3/7 実装済み）を添える。
   - **次の作業**: 4 の結果と、そのための入口（Skill とその引数）。`paused` の TASK なら再開してよいかを質問する。WF-25 に当たれば、`/refactor` の実行の提案を1行で添える。
   - **進行中**: `in-progress`・`paused` の TASK ごとに、現在のフェーズと次の一手。
   - **残作業**: 6 の一覧（実装順。REQ ごとに設計・実装の残り）。
   - **人間の対応待ち**: `draft` の REQ・DES のうち承認待ちのもの、TASK の未解決事項（保留中の P1、残した P2 を含む）、5 で見つけた止まっている資料。
8. 報告の最後に、中断していた作業は「続けて」と言えば `in-progress` の TASK の「次の一手」から再開できると1行で添える。
