# DES-006 立方体

> 実装レベルの粒度で書く。コード本体は書かない。必須項目の定義の正本は guidelines/planning.md。

## 対応要件

REQ-006 の受け入れ基準 1〜3 のすべて。あわせて、DES-004 から回された REQ-004 基準 1 の `cube` を選べる部分を担う。

- 基準 2: REQ-001 基準 1〜5 は、DES-001 の「全図形」の項目（`SHAPES` のすべての値を対象にする #1・#2・#6・#7・#9・#10・#11）が、`cube` を `SHAPES` に足すことで立方体も対象にする。この DES では、立方体が `SHAPES` に入ること、立方体に固有の形（面の上の点と面の向き）、点の数の上限（DES-002）を確かめる。REQ-002 基準 1 は、DES-002 #2 のコマンドを使う DES-006 #10 で確かめる。
- 基準 3: 回転角 0 の正面のフレームを確かめる。

## データ構造

- モジュール内だけで使う定数（`spin.shapes`。名前を `_` で始め、公開しない）:
  - `_CUBE_STEPS = 60`: 1つの面の1辺あたりの点の数。
  - `_CUBE_HALF_SIDE`: 立方体の辺の長さの半分 `a`。値は `BOUNDING_RADIUS / √(1 + 2k²)`、`k = (_CUBE_STEPS − 1) / _CUBE_STEPS`（k ≈ 0.9833、a ≈ 0.5838）。一番遠い点が外接球の上に来るように決める（処理方針）。
- 立方体: 中心は原点、各面は座標軸に垂直。回転角 0 で z が −a の面が視点を正面から向く（REQ-006 基準 3）。
- 1つの面の点: 面の上の2つの座標を、それぞれ `u_i = a × (2i + 1 − N) / N`（i = 0〜N−1、N = `_CUBE_STEPS`）とした N × N 個。面を N × N の正方形のマスに分けたときの、各マスの中心である。残りの座標は面の位置 ±a。
- 面の向き: 面ごとに外向きの座標軸の向き（例: z が −a の面は `(0, 0, −1)`）。長さは 1。
- 面の並び: x が −a、x が +a、y が −a、y が +a、z が −a、z が +a の順。各面の中では、面の上の2つの座標のうち軸の番号が小さい方を外側の繰り返しにする。
- 表面の点の数: 6 × 60 × 60 = 21600 点。DES-002 の上限（30000 点）以下である。
- 一番遠い点: 面の上の2つの座標がどちらも ±a × k の点（各面の4つの角に一番近いマスの中心）で、原点からの距離は `a × √(1 + 2k²) = BOUNDING_RADIUS` になる（REQ-001 基準 4）。

## 処理方針

- **点の作り方（`cube`）**: 6つの面それぞれについて、上の並びで N × N 個の `SurfacePoint` を作り、1つのタプルにまとめて返す。
- **辺の上に点を置かない理由**: 各マスの中心だけを使うので、どの点も1つの面だけに属し、2つの面が同じ位置に点を持つことがない。辺の上に点を置くと、同じ位置に面の向きが違う2つの点ができる。その2点は近さが等しいので、DES-001 の「近さが等しい点は先に処理した点を残す」により、どちらの文字が描かれるかが面の並びで決まってしまう。回転角 0 では、正面の面の縁に側面の文字（反転後の明るさが `.`）が混ざり、REQ-006 基準 3 を満たさない。マスの中心だけを使えば、側面の点は正面の面の点より必ず奥にある。さらに幅 80・高さ 24 では、側面の点が投影されるマスは、正面の面の点が占めるマス（列 26〜53、行 5〜18）に含まれる（側面の一番手前の点は正面の一番外側の点より少し外に投影されるが、同じマスに入る）。そのため、正面のフレームには正面の面の文字だけが残る。試作で、面の並びを変えても正面のフレームの文字が1種類になることを確かめた（TASK-009 の「完了したこと」）。
- **辺の長さの決め方**: 立方体の角（距離 `a√3`）には点がないので、一番遠い点はマスの中心の `(±a, ±a k, ±a k)` になる。その距離が `BOUNDING_RADIUS` になるように `a` を決める。これで、外接球の半径がドーナツと同じ値になる（REQ-001 基準 4）。点のない角の付近も、外接球の中にある点だけを投影するので、DES-001 の「画面の内側に収まる」の議論はそのまま成り立つ。
- **正面のフレームの文字（REQ-006 基準 3）**: 回転角 0 で正面の面の向きは `(0, 0, −1)` で、視点の側を向いているので反転しない。光源との内積は `1/√2`（約 0.707）なので、`floor(0.707 × 12) = 8` で `SHADE_CHARS[8]` の `*` になる。正面の面の点はすべて同じ面の向きを持つので、描かれたマスはすべて `*` になる。
- **点の数（N = 60）**: 回転角 0 で幅 80・高さ 24 のとき、正面の面は横に約 28 マス、縦に約 14 マスを占める。N = 60 なら、点の間隔は横に約 0.47 マス、縦に約 0.23 マスで、面に穴が空かない。1フレームの計算は試作で約 0.026 秒（5回計った最短）で、REQ-002 の 0.1 秒に余裕がある。
- 採用しなかった案:
  - 辺と角の上にも点を置く（各面 (N+1) × (N+1) 点）: 上の理由で、正面のフレームの文字が面の並びに左右される。正面の面を最初に並べれば基準 3 は満たせるが、偶然の並びに頼ることになり、図形を足すときに壊れやすい。
  - 立方体の辺を `2/√3`（角が外接球の上）にする: マスの中心だけを使うと角に点がないため、一番遠い点の距離が `BOUNDING_RADIUS` より小さくなり、REQ-001 基準 4 を満たさない。

### 既存の振る舞いへの影響

変更するのは `src/spin/shapes.py`（関数と定数の追加）と、2つのテストファイル（テストの追加だけ）である。

  - 起動オプションの図形の選択肢と `--help` の表示に `cube` が加わる（REQ-004 基準 1）。
  - DES-002 #2 の人間確認のコマンドが、`cube` の計算時間も表示する（REQ-002 基準 1）。
