# DES-004 不正な入力のエラー

> 実装レベルの粒度で書く。コード本体は書かない。必須項目の定義の正本は guidelines/planning.md。

## 概要
> この設計単位で何を作るか。1〜3文。

コマンドラインで受け取った引数を検証し、不正なときは計算せずに日本語のエラーメッセージを標準エラー出力に書き、終了コード 1 を返す。argparse の既定のエラー処理（英語のメッセージと終了コード 2）は使わない。

## インタフェース
> 公開する関数・モジュール・エンドポイントごとに、入力、出力、エラー（どの条件で何を返すか）。

### `main(argv: list[str] | None = None) -> int`（`warikan.cli`）

- 入力・正常時の出力は DES-002・DES-003 のまま変えない
- 不正な入力のとき: 標準出力には何も書かず、標準エラー出力に `エラー: <メッセージ>` の1行を書き、1 を返す
- 判定は次の表の上から順に行い、最初に当たった1つだけを報告する

| 順 | 条件 | メッセージ |
|---|---|---|
| 1 | argparse が解析できない（例: `--method` の値がない） | `コマンドライン引数が正しくない: <argparse のメッセージ>` |
| 2 | 解析後に余った引数のうち、最初のものが `-` で始まる | `定義されていないオプションがある: <repr(値)>` |
| 3 | 解析後に余った引数のうち、最初のものが `-` で始まらない | `余分な引数がある: <repr(値)>` |
| 4 | 合計金額が指定されていない | `合計金額が指定されていない` |
| 5 | 人数が指定されていない | `人数が指定されていない` |
| 6 | 合計金額の文字列が 20 文字を超える | `合計金額は20文字以内の半角数字（整数）で指定する: <文字数>文字の入力` |
| 7 | 合計金額の文字列が半角数字だけでできていない（空文字を含む） | `合計金額は半角数字の整数で指定する: <repr(値)>` |
| 8 | 人数の文字列が 20 文字を超える | `人数は20文字以内の半角数字（整数）で指定する: <文字数>文字の入力` |
| 9 | 人数の文字列が半角数字だけでできていない（空文字を含む） | `人数は半角数字の整数で指定する: <repr(値)>` |
| 10 | 方式が `organizer-pays`・`collect-extra` のどちらでもない | `方式は organizer-pays（幹事負担）または collect-extra（多めに集める）で指定する: <repr(値)>` |
| 11 | 計算モジュールが `ValueError` を出す（合計金額・人数の範囲外） | DES-001 のメッセージをそのまま使う |

- 2・3 の「余った引数」は argparse の `parse_known_intermixed_args` が返す未解析の引数とする。`-5` のように `-` で始まる値は 2（オプション）として扱う。
- 同じオプションを2回指定したとき（例: `--method collect-extra --method organizer-pays`）は、argparse の既定どおり後の値を使い、エラーにしない。
- `-h`・`--help` は argparse の既定どおり使い方を標準出力に表示し、`SystemExit(0)` を送出する（エラーではない）。`main` はこの `SystemExit` を捕まえず、そのまま呼び出し元へ伝える（`python -m warikan -h` の終了コードは 0）。

## データ構造
> 扱うデータの形、型、制約。

- `_InputError`（`cli.py` 内部の例外。`Exception` を継承）: 判定 1〜10 のメッセージを持つ
- argparse のパーサーは `ArgumentParser` を継承した内部クラスにし、`error` メソッドを上書きして `_InputError` を送出させる（判定 1）。`allow_abbrev=False` で作り、`--meth` のような省略形を `--method` とみなさない（省略形は未解析の引数として判定 2 になる）
- 位置引数 `total`・`people` は `nargs="?"`（省略時 `None`）にし、未指定を判定 4・5 で自分で検出する
- `--method` は `choices` を指定せず、判定 10 で自分で検証する。使い方の表示（`-h`）が DES-003 の `[--method {organizer-pays,collect-extra}]` のまま変わらないよう、`metavar` に `{organizer-pays,collect-extra}` を指定する。`metavar` と判定 10 のメッセージの方式の値は、方式の定数から組み立てる（直接書かない）
- 位置引数を `nargs="?"` にすると使い方の表示が `[total] [people]` になり省略できるように見えるため、`ArgumentParser` の `usage` を `%(prog)s [-h] total people [--method {organizer-pays,collect-extra}]` とする（方式の値は定数から組み立てる）
- 定数: `_MAX_NUMBER_LENGTH = 20`（数値として受け付ける文字列の最大長）。判定 6・8 のメッセージ中の 20 は、この定数から組み立てる

## 処理方針
> 処理の流れ、アルゴリズム、採用しなかった案があれば理由。

1. `parse_known_intermixed_args` で引数を解析し、判定 1〜10 を順に行う（この関数を使う理由は判断の表「解析の関数」を参照）。半角数字の判定は `str.isascii()` と `str.isdigit()` の両方が真であることとする（`isdigit()` だけでは全角数字や `²` も真になるため）。
2. 数字の文字列を `int` に変換し、DES-002・DES-003 の計算と出力を行う。
3. 判定 1〜10 の `_InputError` と、計算モジュールの `ValueError` を `main` で捕まえ、`エラー: <メッセージ>` を標準エラー出力に書いて 1 を返す。それ以外の例外は捕まえない。

- 文字列の長さに上限を設ける理由は、判断の表「文字列の長さの上限」を参照。範囲の判定は計算モジュール（判定 11）に任せる。
- 採用しなかった案は、判断の表「argparse のエラーの扱い」「解析の関数」を参照。

## 判断
> Claude が推奨案で決めた判断（PLAN-18）。人間は承認時にここを確認する。判断がなければ「（なし）」。

| 判断 | 選択肢 | 採用 | 理由 |
|---|---|---|---|
| argparse のエラーの扱い | (a) `error` を上書きして例外にし、検証は自分で行う (b) argparse の英語メッセージを日本語に置き換える (c) argparse を使わず自前で解析する (d) `exit_on_error=False` を使う | (a) | REQ-003 の日本語メッセージと終了コード 1 を満たせ、argparse の版による文言の違いに依存しない。`--help` など argparse の機能はそのまま使える。(b) は文言が版によって変わりうる。(d) は Python 3.12 では引数の不足や未知の引数で `error` が直接呼ばれ、例外にならない |
| 文字列の長さの上限 | (a) 20文字 (b) 上限なし (c) 7文字（1,000,000 の桁数） | (a) | (b) は Python の `int()` が 4300 桁を超える文字列を変換できず例外になる。(c) は `0001000` のような先頭ゼロ付きの正しい値を拒否してしまう。20文字なら先頭ゼロを許しつつ変換は必ず成功する |
| `-5` のような余った値 | (a) `-` で始まればオプションとして報告 (b) 数値なら余分な引数として報告 | (a) | 判定の規則が単純で、どちらの報告でも利用者は「その値が不要」と分かるため |
| 解析の関数 | (a) `parse_known_intermixed_args` (b) `parse_known_args` | (a) | (b) は位置引数の間にオプションを置いた入力（DES-003 までは動いていた）で人数を未指定と誤るため |
| 同じオプションの重複 | (a) 後の値を使う（argparse の既定） (b) エラーにする | (a) | REQ-003 の不正な入力の一覧に含まれず、要件にない仕様を追加しないため |
| エラーの表示形式 | (a) `エラー: <メッセージ>` の1行 (b) argparse 風に使い方も表示する | (a) | REQ-003 が求めるのは「どの値がなぜ不正か」であり、1行で足りるため |
| 計算モジュールの `ValueError` | (a) CLI で捕まえてそのまま表示 (b) CLI でも範囲を検証する | (a) | 範囲の定義とメッセージを計算モジュールの1か所に保つ（DES-001 の判断どおり） |
