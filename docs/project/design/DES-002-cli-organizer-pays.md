## インタフェース
> 公開する関数・モジュール・エンドポイントごとに、入力、出力、エラー（どの条件で何を返すか）。

### コマンドライン

```
python -m warikan <合計金額> <人数> [--method organizer-pays]
```

- `<合計金額>`、`<人数>`: 位置引数。半角数字の文字列
- `--method`: 方式。省略時は `organizer-pays`（幹事負担）
- 出力（標準出力、2行）:

```
1人あたり <1人あたりの額>円
幹事 <幹事の支払額>円
```

金額は3桁ごとにカンマで区切る（例: `1人あたり 3,300円`）。終了コードは 0。

### `main(argv: list[str] | None = None) -> int`（`warikan.cli`）

- 入力: `argv` コマンドライン引数（プログラム名を除く）。`None` のときは `sys.argv[1:]` を使う
- 出力: 終了コード（成功時 0）。副作用として結果を標準出力に書く
- エラー: 不正な入力（整数でない、範囲外、未知の方式、引数の不足・余分）の扱いは REQ-003 の設計で決める。この DES では許容範囲内の入力だけを扱う

### `__main__.py`

- `main()` の戻り値を終了コードにしてプロセスを終了する（`SystemExit`）

## データ構造
> 扱うデータの形、型、制約。

- 方式の値は、文字列 `organizer-pays` だけを扱う（`collect-extra` は REQ-002 の設計で追加する）
- 計算結果は DES-001 の `OrganizerPaysSplit` をそのまま使い、CLI 独自のデータ構造は作らない

## 処理方針
> 処理の流れ、アルゴリズム、採用しなかった案があれば理由。

1. `argparse` で位置引数2つと `--method`（既定値 `organizer-pays`、`choices` は `organizer-pays` だけ）を定義し、`argv` を解析する。`choices` 以外の値や引数の不足は、この DES の時点では argparse の既定の振る舞い（終了コード 2）のままとし、終了コード 1 への変換は REQ-003 の設計で行う。`collect-extra` は REQ-002 の設計で `choices` に追加する。
2. 合計金額と人数の文字列を `int` に変換する。整数として受け付ける形式（半角数字のみ）の検証は REQ-003 の設計で追加し、この変換を置き換える。
3. `split_organizer_pays` を呼ぶ。
4. 金額を `<数値のカンマ区切り>円` に整形し（書式指定 `,` を使う）、2行を標準出力に書く。
5. 0 を返す。

- `main` は終了コードを返し、`sys.exit` は呼ばない。テストから戻り値で終了コードを確かめられるようにするため。
- 整形の処理（金額 → 文字列）は REQ-002 の表示でも使うので、`cli.py` の中で1つの関数にまとめる。

## テスト項目
> 3分類で書く。異常系・境界値・敵対的入力を必ず含める。詳細なルールの正本は guidelines/testing.md。

### 機械検証（テストコードで検証する）

1〜6 は `main` を呼び、戻り値と標準出力の全文（pytest の `capsys`）を確かめる。

1. 正常系: `["10000", "3"]` → 戻り値 0、標準出力 `1人あたり 3,300円\n幹事 3,400円\n`
2. 正常系（方式指定）: `["10000", "3", "--method", "organizer-pays"]` → 1 と同じ
3. 正常系（割り切れる）: `["9000", "3"]` → 0、`1人あたり 3,000円\n幹事 3,000円\n`
4. 正常系（0円）: `["250", "3"]` → 0、`1人あたり 0円\n幹事 250円\n`
5. 正常系（1人）: `["10050", "1"]` → 0、`1人あたり 10,000円\n幹事 10,050円\n`
6. 境界値（表示形式）: `["1000000", "1"]` → 0、`1人あたり 1,000,000円\n幹事 1,000,000円\n`（カンマが2か所）。`["1", "1"]` → 0、`1人あたり 0円\n幹事 1円\n`（カンマなし）。`["1000000", "100"]` → 0、`1人あたり 10,000円\n幹事 10,000円\n`（人数の最大値）
7. 起動口: `sys.executable -m warikan 10000 3` をサブプロセスで実行 → 終了コード 0、標準出力 `1人あたり 3,300円\n幹事 3,400円\n`、標準エラー出力は空

該当しない種類: 異常系と敵対的入力（不正な文字列、範囲外、未知の方式、引数の不足・余分）は、REQ-003 の設計でテストする。この DES の時点では不正な入力に対する振る舞いを定めないため。

### AI レビュー（テストコードでは検証できないもの）

- `cli.py` が計算（切り捨て、幹事の支払額）を自分で行わず、DES-001 の関数に任せている（architecture.md の境界）

| 判断 | 選択肢 | 採用 | 理由 |
|---|---|---|---|
| 引数の形 | (a) 位置引数2つ + `--method` (b) すべてオプション（`--total` など） | (a) | 会計直後に最小の入力で実行できる。必須の値は位置引数にするのがコマンドラインの慣例である |
| 方式の指定値 | (a) 英語 `organizer-pays` / `collect-extra` (b) 日本語「幹事負担」 (c) ローマ字 `kanji` | (a) | ターミナルで日本語入力を切り替えずに打てる。ローマ字の `kanji` は「漢字」と紛らわしい。省略時は幹事負担なので、打つ機会は多めに集めるときだけである |
| 出力の形 | (a) 2行（1人あたり / 幹事） (b) 1行にまとめる (c) 方式名の行も出す | (a) | REQ-001 の必須文字列をそのまま行にでき、読み上げやすい。方式名の行は要件にないため出さない（CODE-14） |
