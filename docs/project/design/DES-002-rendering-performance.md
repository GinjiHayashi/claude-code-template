# DES-002 描画の速さの確認

> 実装レベルの粒度で書く。コード本体は書かない。必須項目の定義の正本は guidelines/planning.md。

## 対応要件

REQ-002 の受け入れ基準 1。

## 概要

REQ-002 の速さを、開発者の PC で計測コマンドを実行して人間が確かめる。DES-001 の実装はすでに基準を満たしているので、コードは作らない。あわせて、これから図形を足す設計（REQ-006・REQ-007）が守る表面の点の数の上限を決める。

## 配置

作成・変更するファイルはない。

## インタフェース

新しく公開するものはない。計測には DES-001 の `spin.rendering.render_frame`・`Rotation` と `spin.shapes.SHAPES` を使う。

## データ構造

- 表面の点の数の上限: 1つの図形につき 30000 点。REQ-006・REQ-007 の設計は、この上限以下の点の数にする。
  - 根拠: DES-001 の実装で、ドーナツ（12000 点）の1フレームの計算は開発者の PC で約 0.017 秒（5回計った最短、2026-10-15）である。1点あたり約 1.4 マイクロ秒なので、30000 点で約 0.042 秒になる。0.1 秒に対して2倍以上の余裕がある。

## 処理方針

- 計測は、test-items.md の DES-002 の人間確認の項目にあるコマンドで行う。このコマンドは選べるすべての図形について、REQ-002 の基準 1 の条件で `render_frame` を計り、図形の名前と最短の秒数を表示する。
- REQ-006・REQ-007 の DES は、データ構造に図形の表面の点の数を書き、この DES の上限（30000 点）以下であることを示す。その DES の test-items.md の機械検証に「表面の点の数が 30000 以下」の項目を置く。
- 計測する範囲は `render_frame` の呼び出しだけとする。表面の点を作る時間（図形の生成関数）は含めない。点は図形ごとに一度だけ作り、フレームごとには作らないため（DES-001 の処理方針）。
- 図形を足した設計（REQ-006・REQ-007）の実装の完了時にも、同じ人間確認を行う（REQ-006・REQ-007 の基準 2）。
- 採用しなかった案:
  - pytest で時間を計る自動テストは採らなかった。現在時刻に依存するテストは TEST-17 で禁じられており、実行する PC の負荷で結果が揺れるため。
  - 速くするための変更（NumPy の利用、点の数を減らすなど）は採らなかった。今の実装で基準を満たしており、NumPy は tech.md で使わないと決めているため。
