# docs 索引

docs 内の固定資料とフォルダの一覧である。**作業を始める前に、この表の「いつ読むか」で読む資料を確認する。**
個々の REQ・DES・ADR・TASK のファイルはここに載せません。各フォルダを直接参照してください。

## guidelines/（全プロジェクト共通の開発ルール）

| パス | 内容 | いつ読むか |
|---|---|---|
| `guidelines/workflow.md` | 探索→計画→実装→レビューのループ、各フェーズの入力・出力・完了条件 | 作業を始めるとき、フェーズを切り替えるとき |
| `guidelines/planning.md` | 要件・設計の書き方、設計に必ず書く項目、質問の進め方、ADR を書く条件 | 要件・設計を書く、または直すとき |
| `guidelines/testing.md` | TDD の手順、テスト項目の3分類、禁止事項、必須ケース | テストを書く前、テストをレビューするとき |
| `guidelines/review.md` | レビュー観点、P0 / P1 / P2 の定義、終了条件 | レビューをする、または受けるとき |
| `guidelines/documentation.md` | 資料の書き方・更新ルール | docs 内の資料を作る、または更新するとき |
| `guidelines/coding.md` | 言語に依存しないコーディング原則 | 実装する前、コードをレビューするとき |
| `guidelines/git.md` | ブランチ、コミット、プッシュ、PR、承認の依頼（承認パケット）、リリース、hotfix | 作業ブランチを作るとき、コミット・PR・承認の依頼をするとき、リリースするとき |
| `guidelines/refactoring.md` | プロジェクト全体の点検の観点（コード・資料間の齟齬）、修正の分類 | プロジェクト全体を点検・リファクタリングするとき |
| `guidelines/templates/` | 各資料のテンプレート（`project/` の資料と同じ名前） | 新しい資料を作るとき |

## project/（このプロジェクト固有の資料）

| パス | 内容 | いつ読むか |
|---|---|---|
| `project/overview.md` | 概要。目的、対象ユーザー、スコープ、成功基準 | 計画を始めるとき、スコープを判断するとき |
| `project/tech.md` | 技術・環境。言語、ツール、開発コマンドの正本 | コマンドを実行する前、ツールを選ぶとき |
| `project/architecture.md` | 構成要素と境界、依存の向き、ディレクトリ構成、命名規則 | 設計するとき、ファイルを新しく置くとき |
| `project/glossary.md` | プロジェクト固有の用語と、コード上の名前（英語） | 用語の意味が曖昧なとき、新しい用語を使うとき、ファイル・コードに名前を付けるとき |
| `project/test-items.md` | 全 DES のテスト項目（DES ごとの見出しに3分類の表） | テストを書くとき、テストをレビューするとき（対象 DES の見出しだけを読む） |
| `project/requirements/` | 要件。`REQ-001-<名前>.md`（1項目1ファイル） | 設計するとき、受け入れ基準を確認するとき |
| `project/design/` | 設計。`DES-001-<名前>.md`（1項目1ファイル） | テストを書くとき、実装するとき |
| `project/adr/` | 設計判断の記録。`ADR-0001-<名前>.md`（1判断1ファイル） | 過去の判断の理由を知りたいとき、判断を変えるとき |
| `project/tasks/` | タスク記録。`TASK-001-<名前>.md`（1タスク1ファイル） | SessionStart hook の表示で足りないとき（`status: in-progress` のファイルを探す） |

オプション資料（リスク、調査メモ、データモデルなど）を追加したら、この表に行を足してください（DOC-09）。
