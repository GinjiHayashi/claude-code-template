# リファクタリング（プロジェクト全体の点検）

実装や変更要求を重ねた後に、コード全体と資料間の整合を点検し、振る舞いを変えずに直すときの基準の正本である。手順は `/refactor` Skill に、実行を提案するタイミングは WF-25 にある。code-auditor と docs-auditor はこの基準で判定する。

差分のレビュー（REV-12）は変更した箇所だけを見るため、複数の変更にまたがって積み重なる問題（ファイルをまたぐ重複、少しずつの肥大、名前の揺れ、資料とコードのずれ）は残りやすい。点検はこれを、リポジトリ全体を対象に探す。

## 全体

- **RF-01** 点検は差分ではなくリポジトリ全体を対象にし、コードの観点（RF-10〜19）と資料の観点（RF-20〜30）で判定する
- **RF-02** 指摘の重要度は REV-01〜03 に従う。P0・P1 には、観点の ID（RF-xx）とは別に、違反した根拠ルールの ID（表の「根拠」列のもの）を書く（REV-04）。根拠ルールのない観点（RF-19）の指摘は P2 とする
- **RF-03** 出力は REV-16・REV-17 の形式とする。「観点」列に RF の ID を書く

## 修正の分類

- **RF-40** 指摘は次の4つに分類する。
  1. **自動修正**: 次をすべて満たす修正。全テストが修正の前後で成功する。テストファイルを変えない。DES のインタフェース欄と、REQ・DES・overview.md の記述の意味を変えない
  2. **テストの整理**: テストファイルの中だけで直せる重複（テストファイルをまたぐ補助関数・定数の重複など。RF-10）で、テストの書き方だけを変えれば直るもの。assert の対象と期待値、テストの名前と `DES-xxx #n` を変えない。TEST-24 の手順で直す
  3. **変更要求の候補**: (1)・(2) を満たさない P0・P1。テストの変更・削除が要るもの（RF-17）を含む
  4. **任意**: P2
- **RF-41** 自動修正のうち、新しいファイルを足すもの（共通部分の切り出しなど）は、architecture.md の配置規則に従い、対応する DES の配置欄に追記する。配置欄の追記は意味の変更に当たらない
- **RF-42** 修正の前に、診断結果（分類付きの指摘の一覧）と修正計画を人間に示し、1回だけ承認を得る。テストの整理（凍結したテストを変える）の対象もこの承認に含める。任意（P2）の指摘は、直すものを人間がこのとき選ぶ（WF-15）
- **RF-43** テストの整理は自動修正より先に行い、凍結してから自動修正に進む（整理したテストで自動修正を守るため）。自動修正は、修正の前にテスト・リント・ビルドがすべて成功していることを確認してから始める。1件直すごとに全テストを実行し、失敗したらその修正を戻して変更要求の候補に移す
- **RF-44** 自動修正を終えたら、コードの差分を code-reviewer で、資料の差分を plan-reviewer でレビューする（REV-12、`/review-loop`）
- **RF-45** 変更要求の候補は、TASK の「未解決事項」に一覧で残し、直すものは `/plan-spec change` で進める（WF-20）
