# テストルール

テストの書き方、TDD の進め方、禁止事項の正本である。test-reviewer はこのルールで判定する。テストの実行コマンドは `docs/project/tech.md` に従う。

## TDD の進め方

| ID | ルール |
|---|---|
| TEST-01 | サイクルは設計（DES）1つ単位で回す。1つの DES について次の順で進め、終えてから次の DES に進む。(1) テストとスタブを書く (2) Red を確認する (3) test-reviewer でレビューする (4) Green (5) Refactor (6) code-reviewer でレビューする |
| TEST-02 | スタブは DES のインタフェースどおりに作り、呼ばれたら「未実装」のエラーを出す以外の処理を持たせない |
| TEST-03 | **Red**: スタブに対して全テストを実行し、全件が「アサーションの失敗」または「未実装エラー」で失敗することを確認する。構文エラー・import エラーによる失敗は Red と認めない。スタブに対して成功したテストは無効なテストとして書き直す |
| TEST-04 | **凍結**: test-reviewer が合格を出した時点で、その DES のテストファイルだけをコミットし、TASK のフロントマター `frozen_tests` にパスを書いて凍結する。Green と Refactor の間はテストファイルを変更しない。TASK が `in-progress` か `paused` の間は凍結が続く。Edit / Write による編集は hook が止める |
| TEST-05 | 凍結後にテストの誤りを見つけたら、実装を止めてユーザーに報告する。ユーザーの承認後に `frozen_tests` から該当パスを消して (1) に戻り、テストの修正、Red の確認、レビューをやり直す。凍結の解除と承認は作業ログに書く |
| TEST-06 | **Green**: 全テスト（既存のテストを含む）を成功させる。リンターとフォーマッターもエラーなしにする |
| TEST-07 | **Refactor**: 振る舞いを変えずにコードを整理する。変更のたびに全テストを実行し、成功を保つ |

## テスト項目

| ID | ルール |
|---|---|
| TEST-08 | テスト項目は DES の「テスト項目」に、次の3分類で書く。**機械検証**: 入力と期待する出力が決まり、テストコードで合否を判定できるもの。**AI レビュー**: 定性的な判断やコード全体を横断した判断が必要なもの（code-reviewer が CODE ルールで判定する）。**人間確認**: 見た目、使い勝手、業務上の妥当性、自動化できない外部環境に依存するもの |
| TEST-09 | 機械検証の項目は、1項目につき1件以上のテストを書く。テスト名またはテストの説明に、DES の ID と項目番号を含める |
| TEST-10 | 人間確認の項目は、実装の完了時に一覧にしてユーザーに確認を依頼する |
| TEST-11 | 公開するインタフェースごとに、次の4種類のケースを機械検証に含める。該当しない種類は、DES に「該当なし」と理由を書く。**正常系**: 代表的な入力。**異常系**: 不正な入力、エラー条件ごとに1件以上。**境界値**: 最小値、最大値、それぞれの前後、空、ゼロ。**敵対的入力**: 極端に長い入力、特殊文字・制御文字、注入を狙った文字列、null・未定義、想定外の型、重複 |
| TEST-20 | カバレッジの数値の下限は設けない。網羅性は TEST-09（設計のテスト項目ごとにテストがあること）で確認する |

## 禁止事項

| ID | ルール |
|---|---|
| TEST-12 | 常に成功するテストを書かない。アサーションがないテスト、`true` を確認するだけのテスト、期待値をテスト対象の実行結果から計算するテストを含む |
| TEST-13 | 実装に、テストの入力を判定して固定値（ダミー値）を返す処理を入れない |
| TEST-14 | テストや処理をスキップして成功させない。スキップ指定、特定テストだけの実行指定、条件付きの早期 return、失敗を握りつぶす例外捕捉を含む |
| TEST-15 | 期待値を決められるのに、広すぎるアサーション（null でないこと、型、例外が出ないことだけ）で済ませない |
| TEST-16 | テスト対象そのものをモックにしない。モックにしてよいのは、テスト対象の外部（ネットワーク、ファイル、時刻、外部サービス）だけとする |
| TEST-17 | 現在時刻、乱数、ネットワーク、実行順に依存するテストを書かない。時刻や乱数は外から渡せるようにする |
| TEST-18 | テスト同士を依存させない。各テストは単独で実行して同じ結果になる |
| TEST-19 | 公開していない内部構造（private な関数や変数）に依存したテストを書かない。インタフェース経由で検証する |
