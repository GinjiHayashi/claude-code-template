# コーディング原則

言語に依存しないコーディング原則の正本である。code-reviewer はこのルールで判定する。数値の基準は、tech.md で選んだリンターが検出できる場合はリンターに任せ、レビューでは扱わない。

## 命名

| ID | ルール |
|---|---|
| CODE-01 | 名前は「何であるか」「何をするか」を表す。`data`、`info`、`tmp`、`flag`、`obj` などの意味を持たない名前は、ループ変数を除いて使わない |
| CODE-02 | 略語は、用語集（glossary.md）にあるもの、または言語・業界で一般的なもの（`id`、`url` など）に限る |
| CODE-03 | 真偽値の名前は、真偽が分かる形にする（例: `is_`、`has_`、`can_` で始める） |
| CODE-04 | 用語集の用語と同じ概念には、用語集と同じ語を使う |

## 関数・モジュールの構造

| ID | ルール |
|---|---|
| CODE-05 | 1つの関数は1つのことだけを行う。関数の説明に「〜して、〜する」と2つ以上の動詞が必要なら分割する |
| CODE-06 | 関数の本体は40行以内とする |
| CODE-07 | ネストの深さは3段以内とする。早期リターンで浅くする |
| CODE-08 | 引数は4個以内とする。超える場合は、関連する引数をまとめたデータ構造を渡す |
| CODE-09 | 1ファイルは400行以内とする |
| CODE-10 | 1つの関数の中で、抽象度の異なる処理（業務の手順と低水準の操作）を混在させない |
| CODE-11 | 依存の向きは architecture.md に従う。禁止された向きの依存を追加しない |
| CODE-25 | 関数の中は意味の段落に分ける。(1) 空行は段階（入力の検証 / 準備 / 本処理 / 結果の組み立てと返却）の境界にだけ1行入れ、境界以外には入れない (2) 1つの段落が10行を超えたら、その段落を名前の付いた関数に切り出す (3) 空行を2行以上続けない。データの定義（定数の表、長いリストなど）は (2) の対象外とする |
| CODE-26 | 書式（インデント、行の折り返し、空白、括弧・引用符の位置、空行の個数）は、tech.md のフォーマッターの決定に従う。CODE-25 は段落を分ける位置だけを決める。CODE-06・CODE-09 の行数は整形後の行数で数える。フォーマッターが「なし」の場合だけ、CODE-25 の (1)・(3) で空行の個数も判定する |

## 重複と簡潔さ

| ID | ルール |
|---|---|
| CODE-12 | 同じロジックを2か所以上に書かない。共通化する（DRY） |
| CODE-13 | 使われていないコード、引数、変数、import、コメントアウトしたコードを残さない |
| CODE-14 | 現在の要件・設計で使わない拡張点（将来のための抽象化、設定項目）を作らない（YAGNI） |
| CODE-15 | 同じ結果を得られるより単純な書き方があれば、そちらを使う（KISS） |

## 値と状態

| ID | ルール |
|---|---|
| CODE-16 | 意味を持つ数値・文字列は、名前の付いた定数にする（マジックナンバーの禁止）。0、1、空文字は除く |
| CODE-17 | 変更可能なグローバル状態を作らない |
| CODE-18 | 副作用（入出力、状態の変更）を持つ関数は、名前か設計でそれが分かるようにする。値を返すだけの関数に副作用を入れない |

## エラー処理

| ID | ルール |
|---|---|
| CODE-19 | 例外・エラーを握りつぶさない。捕捉したら、処理するか、文脈を足して再送出する |
| CODE-20 | 外部からの入力（ユーザー入力、ファイル、ネットワーク、環境変数）は、システムの境界で検証する |
| CODE-21 | エラーメッセージには、何が起きたかと、原因の手がかり（対象の値や ID）を含める。秘密情報は含めない |

## コメント

コメントは3種類に書き分ける。書式（docstring、JSDoc、Javadoc など）と言語は tech.md の「コメントの書式」に従う。

| ID | ルール |
|---|---|
| CODE-27 | **関数の説明**: すべての関数（テスト関数を除く。テストは TEST-09 に従う）に、言語標準の形式で1〜2行の説明を付ける。何をするかと、入力・出力・エラーの要約を書く。処理の手順は書かない |
| CODE-28 | **段落の目的**: CODE-25 で分けた段落のうち、「入力の検証」と「本処理」の段落の先頭に、その段落の目的を1行のコメントで書く。段落が1つだけの関数は CODE-27 の説明で足りるため書かない |
| CODE-22 | **行コメント**: 上の2つ以外のコメントには「なぜそうしたか」（制約、意図、採らなかった案の理由）を書く。コードを読めば分かる「何をしているか」を1行ごとに書かない |
| CODE-23 | コードと食い違うコメントを残さない。コードを変えたらコメントも直す |

## 一貫性

| ID | ルール |
|---|---|
| CODE-24 | 同じ種類の処理は、既存コードと同じ書き方に揃える。新しい書き方を導入する場合は ADR を書く |
